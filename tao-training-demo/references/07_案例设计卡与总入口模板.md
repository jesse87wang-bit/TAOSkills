# 案例设计卡模板、00_从这里开始模板

## 一、案例设计卡（03_讲师参考_不放工作区/案例设计卡.md，用户确认后再动手）

```markdown
# <场景> · 案例设计卡（<日期> 确认）

## 需求
- 场景：<一句话，用户原话>
- 客户：<客户/部门/使用人；或“通用课程案例”>
- 外部连接：<默认：全用样例数据，下单/发消息/审批停在确认>
- 范围：核心链（…→…→…）+ 扩展（…、…）
- 设定：<地点、人物、职级、日期>

## 一句话定位
把<谁>的<什么经验>，做成“<规则卡> + <程序> + 本人确认”。程序算<什么>，AI <查/解释/起草>，本人<拍板/付款/审批>。

## 五项结构
| 项 | 内容 |
| 输入 | … |
| 步骤 | … |
| 规则 | 规则卡 N 条 + 三条铁律 |
| 输出 | … |
| 审核标准 | 数字都来自程序；…；动手类只给确认话术 |

## 两个版本的范围
| | 网页演示版（Claude 做） | WorkBuddy 版 |
| 形态 | 页面：…；身份：…（各能做什么） | 构建00—11：核心链 00—06，扩展 07—09，打包和调用 10—11 |
| 程序 | 同一套 工具/ 和 规则/ | 同左 |
| 演示 | 做成产品什么样 | 怎么一步步做出来 |

## 真假边界
| 内容 | 来源 |

## 规则草案（R01—Rn）
| 编号 | 检查什么 | 怎么判定 | 级别 | 依据 |

## 人必须拍板的事
| 事 | 谁拍板（网页 Demo 的身份） |

## 预埋情形
第一批（6—8 个）：…
新批次（约 6 个）：…
A 类（真实材料里本来就有的）：…

## 课上排法和时长
```

## 二、00_从这里开始.md（包根目录）

```markdown
# <场景> · 从这里开始

<日期> · 王涛 ｜ <客户版/通用课程案例（…全部虚构）>

一句话：……能做：……。下单停在确认，不替人付款。

## 包里有什么
| 文件夹 | 是什么 | 先打开哪个 |
| 01_网页演示版_双击启动/ | Claude 做好的网页 Demo，双击就开：… | 双击 启动.command；说明看 README_演示说明 |
| 02_WorkBuddy版_构建与演示/ | 用 WorkBuddy 自己做出来、演示出来的全套：构建指令 00—11（全文也在手册里）、干净构建工作区、成品工作区、员工一句话入口、技能包、兜底样例 | 构建与演示手册 |
| 03_讲师参考_不放工作区/ | 预埋情形与标准答案、验收用例.py、案例设计卡、Claude 构建记录 | 预埋情形与标准答案.md |
包根目录的 启动网页演示.command 和 01 里的 启动.command 是同一个。

## 三条演示主线，按课时选
| 主线 | 适合 | 用什么 | 时间 |
| A. 网页 Demo | 先看到做成产品什么样 | 01 → 启动.command；脚本在 README 第五节 | 约 40 分钟，开场 3 分钟也行 |
| B. WorkBuddy 成品运行 | 讲一条好指令怎么写，现场让 WorkBuddy 跑 | 02 → 演示说明（第五节有每一步全文） | 约 30 分钟 |
| C. WorkBuddy 从零构建 | 讲怎么一步步做出来，下午学员照着共创 | 02 → 构建与演示手册（第三节构建00—11 全文，第五节课上流程） | 课前 X 小时 + 课上约 30 分钟 |
常用组合：A 开场 3 分钟 + C 主讲；或 A 主讲 + B 现场跑一步。B 和 C 一次课只选一条。

## 第一次拿到包，按这个顺序
1. 双击 01/运行测试.command 看到 OK，再双击 启动.command，照 README 第五节点一遍
2. 读 02 手册第一、二节；课前按第三节在 WorkBuddy 里做一遍，结果填第七节的表
3. 读 03 预埋情形与标准答案，记住关键数字：…
4. 上课前一天：网页版重置；成品工作区 输出/ 清空；<演示日历>；录屏

## 两个版本是什么关系
同一套规则卡、标准 json、程序和输入样例，数字完全一致。网页版在程序外面加了身份权限、决定保存、操作日志、问助理；WorkBuddy 版是学员能自己搭出来、员工能一句话调用的版本。

## 验证情况
已在本地验收：…；没有验收：…。详见 02/交付检查说明.md。
```
