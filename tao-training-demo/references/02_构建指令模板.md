# 构建指令 00–11 模板

这些是通用模板，填尖括号里的内容。写好的 txt 放 02_WorkBuddy版_构建与演示/构建指令/，同时用 scripts/embed_instructions.py 把全文嵌进《构建与演示手册》第三节（每步写：操作、应看到、怎么检查与修复、全文）。

完整范例（12 条全文，含 07—09 三种扩展）：~/Desktop/AI产品库/商务差旅助手Agent/02_WorkBuddy版_构建与演示/构建指令/；客户版范例：examples/报价审查_02/构建指令00-11.md。

## 写指令的规则

- 一条只做一件事。开头说清"这一步做什么、不做什么"
- 写明读哪些文件、输出到哪个文件名，用相对工作区的路径
- 业务规则一条一条写出来，是人给的规矩，不让 AI 自己发明
- 04 必须给已知答案让它逐条对照，并点出 3 个容易出错的坑
- 不在指令里泄露预埋情形以外的提示；答案放工作区外
- 长文档要限定阅读范围（例："规范书151页，只读目录、第1–13页和第146页"），并提醒页序号和页脚页码可能不同
- 需要程序算的，写"数字全部由程序算，不心算"
- 输出类指令最后加一条自查："文档里每个数字都要能在 <xlsx/json> 里找到，找不到的改掉"

## 每一步：模板 + 手册里的"应该看到 / 怎么检查"

### 构建00_检查环境
```
请确认当前工作目录是“WorkBuddy构建工作区”，列出“输入”文件夹里的所有文件。然后执行 python3 --version，把结果原样告诉我，确认是 3.9 或以上。这个助手只用 Python 标准库，不需要安装别的库。最后在 输出/环境检查/ 里写一个内容为“测试”的 UTF-8 文本文件，再读出来，告诉我能不能读写。不要读上级目录。
```
（程序确实要用第三方库时，改成：再执行 python3 -c "import <依赖库>; print('ok')"；缺库就 pip3 install <库名> 后再试一次。新案例优先只用标准库。）
应看到：版本号和 ok。检查：装不上就改走兜底样例讲解，不把模型口述当程序运行。

### 构建01_摸底
```
我是<客户><部门>的，想做一个<场景>助手。先不要动手做，请先读一下"输入/<第一批>"里的<N>份材料，然后告诉我：
1. 每份材料是什么，多少行/页
2. <关键结构>：有哪些列/章节、几个主体、几家/几人；哪些是空的
3. 你觉得可以从哪些角度<审核/整理>
不要下结论<说谁最好/写成品>。
```
应看到：读懂了结构。检查：这一步不求发现问题。讲点：先让 AI 摸底，再给任务。

### 构建02_给规矩
```
下面是我们<部门><做这件事>的规矩。请整理成一张规则卡，保存为 规则/01_<场景>规则卡.md。每条写清：检查什么、怎么判定、问题算高、中还是低（高 = <定义>；中 = 需要澄清；低 = 数据规范）。

1. …
2. …
（10–15 条，来自客户专家经验和已确认规则）

另外<2–3>条铁律也写进去：数字全部由程序算，AI 不心算；<不编数，缺的写【待补】>；AI 只提出问题，不替<业务方>下结论。
```
应看到：规则卡，条数对，每条有判定和级别。讲点：这就是把老师傅的经验写下来。

### 构建03_写程序
```
按规则卡写一个 Python 程序，保存为 工具/<校验>.py：
- 输入：<文件>（默认用"输入/<第一批>"里的，也可以在命令行传入别的文件和输出目录）
- 输出到"输出"文件夹：
  1. <结果>.xlsx，<几>页：问题清单（编号、级别、类别、…、问题、证据、建议动作，按级别排序）、<核心对比页>、<对齐页>、<复算页（用 Excel 公式）>
  2. 校验结果.json（给 AI 读）
  3. 校验摘要.md
- <读大表的性能要求>
写完直接运行，把问题清单和<核心对比>给我看。
```
应看到：程序能跑通，三种输出都有。检查：卡住就让它改只读模式、遇连续空行停。

### 构建04_调试_验收用例
```
我人工核对过这批<材料>，至少有下面 <4> 个问题。请检查你的程序是否都找到了；没找到的，说明原因，修改程序后重新运行，直到全部找到：
1. …（来自预埋清单，写具体，不写编号）
2. …

另外再检查三处容易出错的地方，有问题就改：
- <坑1：例如和平均数比还是和中位数比>
- <坑2：例如不同单位加在一起>
- <坑3：例如同名项对应错>
改完后告诉我：一共多少个问题，高、中、低各几个，<核心结论>有没有变化。
```
应看到：逐条说明找没找到，没找到的改了重跑。检查：对照 样例输出_兜底 的完整清单，还漏的直接告诉它再改。**录屏重点**：第一次没找到 → 指出 → 修好。

### 构建05_固化成指令
```
现在把这个过程固化下来，以后同事拿到新一批<材料>也能用。
1. 写一份指令，保存为 指令_<场景>.txt。内容包括：材料说明 → 先运行 工具/<校验>.py → 读 输出/校验摘要.md 和 校验结果.json → 按规则卡写<意见>（归并成不超过<8>个要点，按<影响程度>排序，每个要点写 发现、证据（注明问题编号）、影响、建议找谁做什么）→ 输出 Word，<1–2> 页。写清楚：数字只能用程序算出的，不心算，不替<业务方>下结论。
2. 按这份指令跑一遍，输出 输出/<正式文档>.docx。
3. 最后自查：<正式文档>里的每个数字，都要能在 <结果>.xlsx 里找到，找不到的改掉。
```
应看到：指令文件 + 正式文档。检查：数字都有出处；没有"建议选某某"。

### 构建06_换新批次验证
```
"输入/<新批次>"是另一批<材料>，<状态说明>。请按 指令_<场景>.txt 处理一遍：<输入>换成新批次的文件，结果输出到 输出/新批次/。
```
应看到：新批次同样三份输出。检查：问题条数和内容对照 样例输出_兜底/新批次/。

### 构建07–09_扩展任务
同一方法换到第二、第三种材料（例：从 PDF 摘审查清单 → 用清单逐条对照两家应答 → 按留痕清单起草请示）。写法同 02–05：先沉淀清单或要求文件到 规则/，再按它做，输出固定文件名。起草类任务要写"结论沿用人工结果，不改结论；缺的写【待补】；文末列与人工结果的差异；注明由 AI 起草、经办人核对后提交"。

### 构建10_打包成技能
```
把今天做的几件事打包成一个 WorkBuddy 技能，名字叫"<english-name>"：
- 包含 规则/ 里的<几>份规则、工具/<程序>
- 写清<几>件事的操作步骤：…
- 写清<几>条铁律：…
按 WorkBuddy 技能的格式保存（根目录 SKILL.md，YAML 含 name 和 description）并压缩成 zip。不得把客户真实材料、答案和旧输出打进技能。装好后告诉我怎么一句话调用。
```
应看到：技能装好并可见。检查：导入不了就通过「技能→添加技能→上传技能」选 zip；界面以当天版本为准。

### 构建11_一句话调用
```
用<技能名>技能，<处理>一下"输入/<新批次>"里的<材料>，出<结果>。
```
应看到：调用了技能，结果与新批次标准答案一致。检查：这条就是课上现场要跑的，彩排时记下用时；没成功加载技能就明说，改用固定指令。


## 07—09 扩展的三种常见写法（商务差旅范例）

| 类型 | 先存的规则 | 程序 | 关键检查 |
|---|---|---|---|
| 定时提醒 / 早报 | 规则/02_提醒规则.md：什么时候发、发什么、只用发出前已查到的数据 | 工具/出行早报.py --date | 前一天的提醒不能用第二天才查到的动态；建定时任务先给人看、演示完删掉 |
| 变动处理（延误、取消、改需求） | 写在指令里：接到通知后至少留多少准备时间、已排除的不算 | 工具/航班变动处理.py --change | 新的到场时间和缓冲；可行办法各自几点出门、差多少钱；消息只起草，退改费写【待补】 |
| 事后检查（报销、归档、结算） | 规则/03_报销检查规则.md：E01—E09 | 工具/报销检查.py | 结论分四种；三项金额加起来等于总额；和待办状态联动（审批没办 → 超标部分个人承担） |

每条扩展指令都按“先把规矩存成文件 → 写程序 → 跑样例 → 三句话说结论 → 每个数字有出处”的顺序写。
