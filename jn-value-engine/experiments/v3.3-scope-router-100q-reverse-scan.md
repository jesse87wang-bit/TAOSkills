# v3.3 Scope Router RC1｜100题专业边界反向筛查

> 性质：单窗口受控模拟路由审查，不是独立跨 Agent 实验，也不使用现实结局作为作答依据。
> 目的：检验 `SPECIALIST_BOUNDARY_ROUTE` 会不会“过度触发”，把本来可以由企业价值引擎完成的经营判断过早甩给专家。

## 1｜筛查方法

对 100 个真实问题先做全量题干扫描，只要题干涉及下列任一专业邻接域，即进入候选池：

- 法律诉讼 / 执行 / 破产程序 / 合同效力 / 公司法；
- 税务申报 / 税务结构；
- 会计确认 / 减值 / 审计；
- Treasury / 衍生品 / 具体对冲执行；
- 监管许可 / 跨境合规 / 制裁 / 行业准入；
- 股权激励 / 员工持股的具体法律税务实施。

候选池再分三类：

- **HARD**：最终可执行结论明显依赖专业事实，必须触发边界路由；
- **PARTIAL**：JN 先完成企业价值判断，仅把局部专业事实交给专家验证；
- **NO-DEFLECT**：虽出现专业词，但核心仍是企业经营/资本/价值问题，不应整体让位。

## 3｜统计

- 全量题目：100
- 进入专业邻接候选池：33
- HARD：15
- PARTIAL：11
- NO-DEFLECT：7
- 其余无需专业边界路由：67

## 4｜反向过触发检查

重点检查 7 道 `NO-DEFLECT`：028 / 068 / 071 / 076 / 080 / 088 / 099。

结果：7/7 均应由 JN 先完成企业价值层判断，不应因为出现董事会、汇率、海外、并购、投资、个人资金等词汇直接让位。

另外检查 11 道 PARTIAL：边界路由只允许把“会改变最终执行结论”的具体专业事实交出去，不得把整个问题交给律师、审计师、银行或顾问。

## 5｜主要发现

### 发现 A｜关键词触发会失败
不能因为出现“董事会、律师、税务、汇率、并购、破产”等词就触发整体让位。必须判断：**最终执行结论是否依赖专业规则/资质事实。**

### 发现 B｜重整类问题最容易出现两种相反 Failure
一端是 `SPECIALIST_OVERREACH`：JN 自己给法律程序结论；另一端是 `SPECIALIST_DEFLECTION`：一句“咨询破产律师”后就不做持续经营价值判断。正确做法是先比较经营价值，再把程序可行性交专业方。

### 发现 C｜跨境问题通常是 PARTIAL，不是整体让位
出海设厂、专利、认证、税务、监管往往需要专业验证，但“是否值得投入、投入节奏、可逆性和尾部风险”仍属于 JN 主战场。

### 发现 D｜Treasury 只让位执行工具，不让位风险预算
JN 可以判断企业是否对汇率过度脆弱、是否应建立风险预算；不应自行指定远期/期权/掉期、具体比例和期限。

## 6｜Failure 复核

本轮未观察到以下结构性问题：

- `SPECIALIST_DEFLECTION`：0 个系统性误触；
- `GENERIC_EXPERT_DISCLAIMER`：规则本身可避免空泛免责；
- `BOUNDARY_VALUE_LOSS`：企业价值判断被保留；
- `SPECIALIST_OVERREACH`：HARD/PARTIAL 路由均明确执行边界。

需要继续长期观察的是：真实用户补充具体合同、税率、会计处理、衍生品参数后，宿主 Agent 是否会从“价值判断”滑入“专业执行”。

## 7｜Release 判断

100题反向筛查未发现 `SPECIALIST_BOUNDARY_ROUTE` 的系统性过触发。

结论：**RC1 可进入正式 v3.3 Release。**

正式版只合并：
1. `SPECIALIST_BOUNDARY_ROUTE`；
2. 四个 Failure 标签；
3. 边界输出结构；

不修改 v3.1 Decision Engine、不修改 v3.2 Interaction Router、不改主 Schema 与视觉体系。
