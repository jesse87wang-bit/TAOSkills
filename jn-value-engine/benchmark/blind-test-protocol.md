# jn-value-engine v3.1 RC1｜跨 Agent 盲测协议

## 目的
验证 v3.1-RC1 是否在真实企业价值问题上稳定优于 v3.0、资深 CFO Prompt 和普通 GPT，同时避免“同一模型自己出题、自己回答、自己评分”的自证偏差。

## 四组被测系统
- A：普通 GPT（不加载额外 Prompt/Skill）
- B：资深 CFO Prompt（固定版本，不得针对测试题临时修改）
- C：jn-value-engine v3.0（main 正式版）
- D：jn-value-engine v3.1-RC1（本分支）

测试执行者知道系统身份；Judge 不知道。提交给 Judge 前随机映射为 W/X/Y/Z，并对每题重新随机排序，避免位置偏差。

## 强制公平条件
1. 同一道题必须使用完全相同的用户输入。
2. 禁止任何系统搜索、检索或推断该真实案例的现实结局。
3. 不向被测系统提供评分 Rubric、参考答案或其他系统的输出。
4. 同一轮尽量使用同一基础模型、相同 thinking effort、相同上下文窗口与温度/采样设置（如平台可控）。
5. CFO Prompt、v3.0、v3.1 在测试开始后冻结，不得边测边改。
6. 缺数据时允许提出“需验证/待量化”，不得因没有数据而编造数字。
7. 每题独立新会话，避免前题泄漏。
8. 图片/路线图不参与决策质量主评分；先只评文字判断。视觉一致性另测。

## 测试集
### Phase 1｜10题核心盲测
从 regression-20 中分层抽取：
- 2题现金/融资
- 2题增长/第二曲线
- 2题高不确定投资
- 1题数字质量
- 1题重大交易/控制权
- 1题表外风险
- 1题简单经营决策（检测 OVERTHINKING_TRAP）

### Phase 2｜20题回归
Phase 1 通过后跑完整 regression-20。

### Phase 3｜100题 Benchmark
只有 v3.1-RC1 在 Phase 2 达到发布门槛后才运行，避免为弱版本浪费测试成本。

## 120分评分 Rubric
每项 0–10 分：
1. 问题重构
2. 关键矛盾
3. 经营机制
4. 生命周期/行业适配
5. 资本效率
6. 第三方案/选择设计
7. 证据与下注
8. 现金与尾部风险
9. 执行性
10. 证伪/反转条件
11. 数字质量与结构穿透
12. 重新设计能力

### 评分锚点
- 0–2：缺失/明显错误
- 3–4：提到但机械、泛化
- 5–6：基本正确，有一定可用性
- 7–8：具体、因果清楚、能支持行动
- 9–10：显著改变决策质量，且边界清晰

Judge 必须逐维给分并写 1 句理由，不允许只给总分。

## 失败模式标签
每题同时标注是否出现：
- FM-01 METRIC_TRAP
- FM-02 A_B_TRAP
- FM-03 GROWTH_TRAP
- FM-04 FINANCING_TRAP
- FM-05 STORY_TRAP
- FM-06 OVERTHINKING_TRAP

## 发布门槛
v3.1-RC1 合并 main 必须同时满足：
1. 对 v3.0 的平均总分提升 >= 8%。
2. “数字质量与结构穿透”+“重新设计能力”平均提升 >= 20%。
3. 原有10个维度中，没有任何一个平均下降 > 5%。
4. OVERTHINKING_TRAP 发生率不高于 v3.0。
5. 平均文字长度相对 v3.0 增幅 <= 20%。
6. 至少两个不同 Judge 的系统排序方向一致；若分歧明显，进入人工复核而非自动发布。

## Judge Prompt
你是一名独立企业价值决策评审。你不知道以下答案由什么系统生成，也不要猜测身份。只根据答案本身评分。

任务：针对同一个企业问题，对 W/X/Y/Z 四份匿名答案分别按 12 个维度 0–10 分评分。每一维写一句具体理由。随后列出每份答案触发的 Failure Mode，最后给出总分和排名。

规则：
- 不搜索现实案例结局。
- 不因答案更长而加分。
- 不因使用更多财务术语而加分。
- 奖励因果清晰、能改变行动、知道边界、能提出可证伪条件的答案。
- 若答案编造用户未提供的数字，应明确扣分。
- 若简单问题被无必要复杂化，标记 OVERTHINKING_TRAP。

## 结果记录
每一题至少保存：case_id、匿名映射、四份原始回答、Judge逐维评分、总分、Failure Mode、字数、Judge版本/模型、测试日期。

## 禁止公开宣称
在跨 Agent 盲测完成前，不得公开声称“v3.1 比 v3.0 提升 X%”或“显著优于 CFO/GPT”。此前内部控制测试只能标记为开发阶段结果。
