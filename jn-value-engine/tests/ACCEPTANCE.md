# jn-value-engine 验收测试

## 必过测试

1. 显式调用 Skill：必须出现固定标题与 01–09。
2. 在 09 完成前：图片调用次数必须为 0。
3. 缺少任一模块：验证失败，禁止图片。
4. 04 无 A/B/C：验证失败。
5. 08 不是 4 个 Gate：验证失败。
6. 09 无“什么会让我改变判断”：验证失败。
7. 图片先于文字：整次交付 INVALID。
8. 图片不得改变文字阶段结论。
9. 用户只给少量信息：允许阶段性判断，不得编造精确数据。
10. “缺钱”：必须先检查经营/交易/资本占用重构，不能默认融资。
11. 用户可见第一个字符必须属于正式标题，标题前不得出现调用、读取或执行说明。
12. 第09模块最后结论与路线图之间不得出现校验、解锁、图片规范、生成进度或等待说明。
13. 路线图之后不得追加完成说明、结论复述、路径、链接或尾声。
14. 路线图必须读取并对照 `assets/tf-roadmap-master.jpeg`（“新能源设备公司资金链修复”版），不得使用纺织企业版、整张深蓝旧版或通用咨询模板。
15. 图片必须保持固定顺序：行业 Hero、全宽01决策结论、同排02–05四等栏、06 A/B/C、07阶段路线、08指标块、09恰好4个闸门、10未来1–2周行动和 TF Footer。
16. 图片顶部与 Footer 的视觉品牌不得出现 `JN`；只允许 `TF`、`TF 企业价值引擎`；右侧 Skill 署名必须准确保留 `jn-value-engine`，不得出现 `tf-value-engine`。
17. 06 A/B/C 每栏必须有绿勾/红叉和底部态度条；推荐方案必须使用浅金/绿色强调。
18. 07 必须使用连续蓝色箭头；每阶段箭头下方必须独立出现 `目标：`、`动作：`、`进入条件：`。
19. 02、05 使用图标行；03 使用大型核心问题；04 使用两个上下矛盾子卡。四栏不得退化为同构项目符号卡。
20. 08、09、10 必须采用母版的横向等宽小卡结构；大面积留白、文字极小或模块顺序改变均判失败。
21. 各区高度必须落入 SKILL.md 规定的母版比例区间；不得为迁就文案任意拉高某一模块。
22. 条件允许时必须进行同尺寸闪烁/半透明叠图检查；固定边界出现明显双边则判失败，无法叠图不得宣称完全符合。

## 回归案例

- 新能源设备公司：订单好、回款慢、拖欠供应商500多万元、资金链断裂；问融资还是缩业务。
- 新能源设备公司资金链修复：验证唯一母版的完整视觉结构。
