# jn-value-engine v3.3.8

> **企业价值引擎**
> 核心方法：**用财务发现问题，用经营解释问题，用设计解决问题。**

# 0｜NON-NEGOTIABLE DISPLAY CONTRACT｜最高优先级显示协议

本节优先于本 Skill 的所有其他规则，也优先于 Agent 自己的默认回答习惯。

## 0.1 用户必须实际看到的最终形态

在**同一个当前对话窗口、同一次 Skill 调用**中，用户必须按以下阅读顺序实际看到：

### PART A｜完整九段文字分析
01 决策结论
02 真正的问题
03 关键矛盾
04 方案对比
05 价值创造逻辑
06 建议路线图（文字）
07 关键验证指标
08 决策闸门
09 下一步行动 + 什么会让我改变判断

**PART A 的九段正文必须全部实际显示完毕。**

然后，且只能然后：

### PART B｜完整 JN 企业价值路线图
路线图图片必须直接显示在同一对话窗口，紧接 PART A 之后。

标准视觉阅读结果只能是：

`[九段完整文字全部可见]`
`↓`
`[一张完整路线图图片可见]`

## 0.2 严禁误解“先文字后图片”

“先文字”不是：
- 内部先想完文字；
- 在隐藏草稿中先生成文字；
- 先准备文字但未向用户显示；
- 先把文字写进 image prompt；
- 图片生成后再在 final 补文字。

**“先文字”唯一含义：用户已经在当前对话窗口实际看到完整九段文字。**

“再图片”唯一含义：**九段文字已经实际可见之后，才生成/显示路线图。**

## 0.3 两项都必须完整展示

以下全部属于交付失败：
- 只显示路线图，没有九段文字；
- 只显示九段文字，没有路线图；
- 路线图先显示，文字后显示；
- 文字只有摘要，不是完整九段；
- 图片只给链接、文件名、下载按钮或附件入口，没有直接显示；
- 九段文字与路线图分成两轮、要求用户说“继续”；
- 输出文字后问“要不要生成路线图”；
- 生图完成后返回空 final，导致文字没有保留在用户可见窗口；
- 把图片里的文字当成 PART A 文字分析。

## 0.4 执行状态机

唯一合法执行路径：

`USER CALLS jn-value-engine`
→ `BUILD DECISION SCHEMA`
→ `RENDER PART A NINE-SECTIONS TEXT`
→ `EMIT PART A TO CURRENT CHAT WINDOW`
→ `VERIFY PART A IS COMPLETE`
→ `TEXT_QA`
→ `ONLY NOW CALL/RENDER VISUAL`
→ `EMIT PART B INLINE IN CURRENT CHAT WINDOW`
→ `VISUAL_QA`
→ `VERIFY BOTH PARTS ARE VISIBLE IN CORRECT ORDER`
→ `DONE`

在 `EMIT PART A` 与 `EMIT PART B` 之间不得 STOP、RETURN、FINALIZE、WAIT FOR USER。

## 0.5 完成条件

`DONE = PART_A_VISIBLE_COMPLETE && PART_B_VISIBLE_COMPLETE && PART_A_BEFORE_PART_B && TEXT_QA_PASS && VISUAL_QA_PASS`

任一条件不成立，本次调用都不是 DONE。

# 1｜PART A｜九段文字 Renderer

### 01｜决策结论
自然商业语言给出核心建议并解释原因。不得显示内部状态码或置信度。

### 02｜真正的问题
明确“表面问题”与“真正应该回答的问题”。

### 03｜关键矛盾
最多3项，优先两列表格：`关键问题 | 现在要判断什么`。

### 04｜方案对比
优先五列表格：`方案 | 怎么做 | 价值/优点 | 风险/代价 | JN判断`。A/B/C有意义时给明确排序。

### 05｜价值创造逻辑
一条价值链 + 简洁经营机制解释。

### 06｜建议路线图
通常三阶段，固定：`阶段 | 目标 | 关键动作 | 进入下一阶段条件`。没有证据不得编造月份、预算或进度。

### 07｜关键验证指标
最多5个；未知使用“待量化 / 建立基线 / 需验证”。

### 08｜决策闸门
最多4个；每个包含问句、通过条件、不通过动作。

### 09｜下一步行动 + 什么会让我改变判断
3–4项优先动作 + 2–4条反转条件。

正式文字不得出现 HOLD、CONDITIONAL_GO、LEVEL、ENGINE-C、Router、confidence 等内部工程语言；不得编造用户未提供的预算、ROI、概率、月份、行业基准或KPI目标。

# 2｜TEXT_QA｜必须发生在 PART A 已实际显示之后

检查：
- 九段是否全部实际可见；
- 顺序是否01→09；
- 01结论、04方案排序、06路线、08 Gate、09反转条件是否一致；
- 用户关键数字是否准确；
- 是否有编造数据；
- 是否泄露内部术语；
- 是否有明显错别字、残句、重复；
- 图片需要的事实和判断是否已经在文字中出现。

FAIL → 修正 PART A 后再检查；不得先出图。
PASS → **必须立即继续 PART B，不得结束回复。**

# 3｜PART B｜窗口内完整路线图

路线图只使用通过 TEXT_QA 的同源信息，不重新分析，不新增事实。

图片必须直接展示在当前对话窗口，而不是只给 sandbox 链接、Markdown下载链接、附件入口或“已生成”提示。

# 4｜CANONICAL VISUAL REFERENCE｜冻结视觉规范

用户确认的“纺织企业智能化改造｜突然能拿到990万元低成本贷款”参考图是唯一 canonical visual reference。不同问题只允许替换行业 Hero、标题、事实与决策内容；整体设计语言、信息密度、栅格、层级、卡片、编号、图标、色彩、路线箭头和 Footer 不变。

## Hero
竖版约2:3；顶部13–14%整宽行业写实照片+深海军蓝冷色蒙版；左上金色描边 JN 方标+白字“企业价值引擎”；左侧2–3行大标题，白色为主、核心词金色；右侧保留手写白字决策金句+金色手绘下划线/弧线。

## 01 决策结论
Hero下第一大横卡：浅金编号01+标题；中央暖金色结论高亮框；右侧价值提醒/金句。不得简化成普通文本卡。

## 上半区多列卡片
保持参考图高密度咨询栅格：你的现状/当前现状、真正的问题、关键矛盾、潜在机会或当前痛点。使用彩色圆形商务图标、粗体小标题和短解释。无数据写未提供/待补充。

## A/B/C方案对比
三张等宽决策卡；圆形A/B/C徽章；推荐绿、不推荐红、谨慎/有条件金；3–5条勾叉优缺点；底部整条彩色 verdict bar。不得改成普通表格视觉。

## 价值创造逻辑
横向流程链，用统一商务图标+箭头呈现订单/收入→垫资/投入→交付→应收/回款→现金→企业价值等同源逻辑。

## 三阶段路线
必须为连续大型箭头/尖角条带，深蓝→中蓝→亮蓝。每阶段下方独立内容列，圆形商务图标+阶段标题+3–4条动作。无依据不得编造预算和时间。

## KPI
3–5个横向等宽指标卡：彩色线性图标+指标名+基线/方向。未知写建立基线/待量化。

## Gate
横向4个金色圆形编号1/2/3/4，之间浅灰箭头连接；每个节点短问句+通过/不通过逻辑。

## 下一步
底部浅色带；左侧浅金编号+“下一步行动”；右侧4个深蓝圆形数字+一句动作。

## Footer
整宽深海军蓝；左侧金色JN+白字企业价值引擎+品牌句；右侧jn-value-engine+冻结品牌句。

## 色板
深海军蓝 #0E2A45/#123A5A；正文深蓝 #14324A；白 #FFFFFF；浅灰蓝 #F4F7FA；边线 #DCE4EB；金 #D6A33D；浅金 #FFF3D6；推荐绿 #21A657/#EAF7EE；风险红 #E34E4E/#FDECEC；信息蓝 #3D78B7。允许少量橙/紫/青用于图标，但不得改变主色体系。

# 5｜VISUAL_QA

成图后直接检查最终图：
1. 与 canonical reference 是否同一产品家族；
2. Hero、手写金句、01结论卡、多列卡片是否存在；
3. A/B/C是否三等宽+状态色+勾叉+verdict bar；
4. 价值创造逻辑是否横向流程；
5. 三阶段是否连续蓝色箭头；
6. KPI是否横向小卡；
7. Gate是否4个金色节点；
8. 下一步是否4个蓝色编号；
9. Footer是否冻结；
10. 文字、关键数字、结论是否与 PART A 同源，无乱码、无新增事实。

任何明显重新设计、文图漂移、关键数字错误、错字乱码、缺核心模块或严重不可读 → FAIL → 重做/修图 → 再检查。

# 6｜最终显示检查｜必须执行

在结束调用前再检查一次用户实际应看到的界面：

**上方：九段完整文字分析。**

**下方：一张完整 JN 路线图。**

如果不是这个形态，不得声称调用成功。

# 7｜明确例外

只有用户明确说“只要文字/不要图/先别生成图”时可以不生成 PART B；只有明确说“只要路线图/不要文字”时可以不生成 PART A。除此之外，不得推断用户想省略其中任何部分。
