# tao-spatial-video｜口播原片 → 空间感玻璃卡 4K60 成片

第一条成品（风格基准）：`自媒体/30-口播稿/加更-WorkBuddy还是豆包工作/成片_WorkBuddy还是豆包工作_4K60.mp4`

**工具包**：本 skill 目录下的 `toolkit/`（先读 `toolkit/README.md`；时间轴和素材写法照 `toolkit/templates/seq_example.py`、`toolkit/templates/sprites_example.py`）。
「自媒体」工作台里已有带音效的本地副本 `自媒体/bin/spatial_video/`，有就优先用它；没有就把 `toolkit/` 拷到工作目录，并按 `toolkit/sfx/README.md` 准备 6 个音效。下文 `<工具包>` 指其中之一。

## 用户要的效果（已确认，别改）

- **人物始终居中是主体**，背景就是**真实房间**，不虚化、不调色、不加紫色滤镜。原片像素不动，只改卡片所在区域。
- **玻璃拟态卡片从人物两侧、从身后浮出来**，带轻微 3D 透视（左卡 ry=+26°，右卡 ry=−26°），**内侧边缘被人的头和肩挡住**，墙上有淡淡投影。人和 UI 在同一个空间里，不是「视频上盖几张 PPT」。
- 发光大字、结论条压在胸前（前景层）；顶部挂章节标（01/02/03…）。
- **每个元素卡着口播关键词弹出**，一层一层出现，配剪映音效。
- **输出 = 原片同规格**：2160×3840、60fps、H.264 High、CRF 15、bt709。交付前必须用 probe 核对分辨率、帧率、帧数。
- **画面上不出现「评论区扣 xx」这类引导评论/私信的字样**（平台不允许）；字幕里口播说到「评论区」的，把这三个字删掉（如「有需要的可以告诉我」）。

## 输入

用户会给：原视频位置（一般在桌面 `自媒体/` 下，iPhone 竖拍 4K HDR .MOV）+ 口播稿（贴在对话里或 md 文件）。缺哪样就问哪样，其余直接做，**不用先出样片**，但渲染前要做静帧自检。

## 环境分工

| 在哪 | 做什么 |
|---|---|
| 用户电脑的 Linux 环境（device_bash） | 原片在这：识别、对齐、调色抠像合成、编码、混音 |
| 云端容器（有 Chromium/Playwright） | 渲染玻璃卡 PNG、4K 字幕 PNG、静帧预览 |

原片（几百 MB）**不要往云端传**；只把小文件在两边搬。

## 流程

### 0. 准备
1. 请求访问 `~/Desktop/自媒体`（device_request_folder_access）。读 `CLAUDE.md` 和 `00-定位/账号宪法.md`，按会话协议跑 `python3 bin/status.py`、`python3 bin/log.py --show`（注意是 `python3`，不是 `.venv/bin/python`）。
2. 电脑上：`bash <工具包>/device/prep.sh`（装依赖、下模型到 `~/work/sv`）。
3. `bash <工具包>/device/probe.sh <原片>`：看 `color_transfer`（`arib-std-b67` = HLG，要色调映射，`SRC_HDR=True`）、分辨率、时长。`N_SRC = floor(时长×60)`。不是 2160×3840 的素材要先跟用户说。
4. 项目文件夹：`30-口播稿/<选题ID或加更-短标题>/`，中间文件放它下面的 `_工作文件/`。

### 1. 听写与对齐
1. `python3 <工具包>/device/asr.py <原片> ~/work/sv/asr.json`（SenseVoice，带逐字时间戳）。
2. 用识别结果对照口播稿，写**实际念出来的**校对版字幕行（一行 ≤16 字，产品名写对：识别常把 WorkBuddy 听成「五合八」「克巴里」），存 `lines.txt`。以录音为准，不是以文稿为准。
3. `python3 <工具包>/device/align.py asr.json lines.txt lines.json` → 每行起止时间；`lines_chars.json` 用来查关键词出现的秒数（卡点用）。
4. 同时存一份 `字幕.srt` 和实录版 `口播稿.md` 到项目文件夹。

### 2. 设计时间轴（最花心思的一步）
按口播结构分章（开场钩子 → 第一/二/三点 → 收尾），每章：
- 章节开始：顶部章节标 `badge("01","生态")`，y=330，整章常驻。
- 讲 A 情况 → 左侧玻璃卡（A 色：青蓝）；讲 B 情况 → 右侧玻璃卡（B 色：紫靛）。**颜色和左右位置全片固定**。
- 列举类内容用 `list_panel`，配 `wipe` 逐行亮起，行出现的时刻对准口播里说到那个词。
- 小结论 → 胸前结论条 `verdict` / 判断行 `judge`；金句 → `glow_text` 大字（可加 `strike` 划掉动画）。
- 一段话结束就让卡片退场（`out`），同时画面上**最多**：左卡 + 右卡 + 胸前 1–2 行字 + 顶部章节标。
- 片尾：电脑屏幕 `laptop`（示意界面，标「示意」）+ 评分面板 `rating_panel`（空星，不写假分数），片尾定格 1.5 秒。

版式常量（1080×1920 布局坐标，渲染时自动 ×2）：

| 元素 | 位置 |
|---|---|
| 左/右玻璃卡 | x=222 / x=890，y=760，s=0.92，ry=±26（合成器会按人头位置自动缩小外移，保证字不被头挡住） |
| 胸前大字/结论条 | y≈1195，第二行 y≈1310 |
| 顶部章节标 | y=330 |
| 字幕 | y=1478（自动） |
| 不放东西 | 顶部 0–220、底部 1500 以下（平台 UI） |

动画参数：面板 `dur=.65` 从人物身后 (460/640, 790) 转出；前景字 `pop` 放大落下；`float` 轻微漂浮；`streaks` 在章节切换处加扫光；`boost` 在重音处让卡片光晕闪一下。

时间轴写成一个 `seq.py`（照 `templates/seq_example.py`），里面同时写 `MOV / SRC_HDR / N_SRC / HOLD / TOTAL_SEC / SFX` 和 `seq()`。

### 3. 素材与字幕（云端容器）
1. 把工具包的 container、templates、fonts 传到容器。
2. 写 `sprites.py`：用 `sprites_lib.py` 的组件生成全部素材，`render_all(S, 'sp3')`（3 倍 PNG）。素材名要和时间轴里的 `sp=` 一一对上，渲染后核对没有缺的。
3. `python3 container/subs.py lines.json sub4k <TOTAL_SEC>`（最后一句延到片尾）。
4. 文字不能溢出：`list_panel` 标题 ≤7 个汉字（长了调 `tsize`），`big_card` 大字 4 个汉字最佳（长了调 `bsize`），字幕 >2100px 要拆行。

### 4. 静帧自检（渲染前必做）
电脑上用 zscale 色调映射抽 10–15 张 4K 静帧（每章 1–2 张，`-q:v 3` 的 jpg），打包传到容器，跑：
`python3 container/preview.py seq.py sp3 sub4k 预览.jpg 秒:静帧.jpg ...`
逐张看：字有没有被头挡、卡片有没有溢出、胸前字有没有和字幕打架、左右是否平衡。改到满意再渲染。

### 5. 音效（混音在电脑上）
音效在 `<工具包>/sfx/`（剪映音效，使用者需有授权），规则：

| 音效 | 用在 |
|---|---|
| `deng`（科技点击系统音，「噔-楞」） | 每张玻璃卡弹出 |
| `app`（App 界面点击） | 小图标、列表行亮起（增益 0.5）、VS |
| `tone`（柔和系统音） | 胸前大字/结论条出现 |
| `ding3`（科幻三连叮） | 重音：碰撞、划掉、盖章、面板逐行亮起 |
| `xp`（系统提示音） | 章节标出现 |
| `ui`（按钮点击） | 副标题、提示条 |

音效时间 = 元素出现时刻 −0.02 秒；声像跟卡片左右（±0.5）。`python3 device/mix.py seq.py audfull.wav`（人声 + 音效，响度 −16 LUFS）。用户没要求就不加 BGM。

### 6. 分段渲染（电脑上）
1. 把 `sp3/`、`sub4k/`、`seq.py` 打包传到电脑（`device_commit_files` 单文件 ≤20MB，超了先 `split -b 18m` 分片再 `cat`；传完核对 md5）。
2. 设环境变量 `SV_SPRITES`、`SV_SUBS`、`SV_RVM=~/work/sv/rvm.onnx`，按段渲染：`bash device/rc.sh <工作目录> seq.py <起始帧> <结束帧>`。
3. **每次 device_bash 只跑一段、≤450 帧（约 130–150 秒）**，逐段看输出的 `frames=` 和 `expected=` 一致，不一致就把这段拆小重跑。总帧数 = N_SRC + HOLD×60。
4. 全部完成后 concat（`-c:v copy`）+ 混音轨（AAC 320k）+ `-movflags +faststart`，输出到项目文件夹 `成片_<短标题>_4K60.mp4`。

### 7. 交付前核对
- `probe.sh 成片`：2160×3840、60/1、帧数 = 预期、时长对、bt709。
- 抽 1 秒一帧的缩略图总览（`fps=1,scale=180:320,tile=12x5`），从头看到尾：卡片不缺、不被挡、字幕对。
- 抽几个分段接缝，确认没有跳帧。
- 用 `python3 bin/log.py 剪辑 <ID> 0 "..."` 记日志。

## 内容检查（每条都做）
- 账号宪法：屏幕文字不用「老板/高管/管理者」称呼观众；不虚构数据和案例。
- 事实类说法（产品支持什么、整合了什么）上屏前查官方来源；会变的加「截至 X 年 X 月 · 以官方为准」，引用别人的写「来源：xx 官方」。示意画面标「示意」。
- 口播里提到的 CTA 物料（如「评测打分表」）在 `40-素材库/物料/` 里不存在时，交付时提醒用户：物料没做出来前不能发，并主动提出帮做。

## 踩过的坑
- **iPhone 原片是 HLG/杜比视界**：不做色调映射直接转，画面发灰、人物过曝。必须用 comp4k.py 里的 `TONEMAP`（zscale linear npl=100 → hable → bt709）。
- **电脑上的后台进程活不过一次 device_bash 调用**（nohup/setsid 都没用），所以只能分段、每段 175 秒内跑完。
- **只能单进程渲染**：两个 4K 渲染并行会把 3.9GB 内存吃满，编码器被系统杀掉（现象：BrokenPipe、moov atom not found）。
- 别把脚本命名成 `chunk.py`（会顶掉 Python 标准库，`wave` 模块跟着报错）。
- `device_stage_files` 传大文件经常超时，传 ≤6MB 的分片更稳；`device_commit_files` 提交 mp4 会被加一小段元数据，md5 会变但能正常播放，其他格式不受影响。
- 连接电脑的文件夹不能删文件（rm 报 Operation not permitted），临时文件都放 `_工作文件/`，最后提醒用户整个删掉；需要删除时用 device_request_delete_permission。
- 原片是可变帧率（约 59.3fps），统一用 `fps=60` 转成恒定 60 帧，帧号 = 秒 × 60。
