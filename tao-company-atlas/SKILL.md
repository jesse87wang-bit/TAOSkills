# tao-company-atlas｜一家公司 → 3D AI 运转全景 + AI 全貌蓝图 + 两份讲解稿（工具包 v1.0.4）

用户每给一家新公司（公司名，加上他手上的资料），就交付四样东西：

1. **`<简称>AI运转全景`**（3D 页）：园区全景（一单业务走完全公司，8 步）、组织·过渡态、组织·理想态、**老板驾驶舱**（每家必有）。
2. **`<简称>AI运转全景：给<老板>的讲解稿`**（Docs）
3. **`<简称>AI全貌蓝图`**（9 个板块的长页）
4. **`<简称>AI全貌蓝图：给<老板>的讲解稿`**（Docs）

**效果底线：只能比第一家好，不能比第一家差。** 第一家的成品在用户的 artifacts 里（`list_artifacts` 搜“AI 运转全景”“AI 全貌”），做新公司前打开看一眼，交付前拿新页逐项对比。不许为了省事删视图、删步骤、删图表、减数量。

工具包：GitHub `jesse87wang-bit/TAOSkills` 的 `tao-company-atlas/`。先读里面的 `README.md`（用法、镜头、积木、踩过的坑）、`CONFIG.md`（字段和硬性数量）、`NARRATION.md`（讲解稿写法）。引擎不随公司改，新公司只写一份 `configs/<公司>.js`。

## 0. 环境（每个新会话都要做）

```bash
cd /home/claude && git clone --depth 1 https://github.com/jesse87wang-bit/TAOSkills && cp -r TAOSkills/tao-company-atlas atlas && cd atlas && npm install
```
Playwright + Chromium 用容器预装的，不要重装。

## 1. 研究：先把这家公司查透（自己做，不派子代理）

按顺序，全部做完再动笔：
- **记忆**：`memory_list`/`memory_read` 里关于这家公司、这个老板、这个项目的文件；`conversation_search` 搜公司名和老板称呼，看以前聊过什么（培训、诊断、老板关心什么）。
- **用户给的资料**：附件、贴的文字、链接，全部读完。
- **网上**：官网、年报/招股书/问询回复（上市或拟上市公司必查）、近一年新闻、行业报告。重点拿到：收入结构（各业务占比）、经营模式和正在怎么变、主链有哪些环节、规模（门店/机房/工厂/员工）、地域布局、老板公开讲过的战略、行业里 AI 已经做成的案例。
- 每条事实记下出处，存到 `research/<公司>.md`（本地，不进仓库）。查不到的不编：页面上不写具体数，讲解稿里改成“停下来问”。

只有两类信息查不到时才问用户（一次问完，用 AskUserQuestion，同时继续做别的）：老板怎么称呼；用户自己掌握的内部情况（痛点、阶段、谁对接）。其余自己判断，在交付消息里说一句按什么判断的。

## 2. 诊断：想清楚再写配置

写下这几条判断（就是配置的骨架）：
- 这家公司**靠什么赚钱**，利润卡在哪；经营模式**正在往哪转**。
- **一单业务的主链**：8–10 环，从获客/采购到收钱。3D 园区的 8 步和蓝图 02 的主链都从这里来。
- 每一环**现在的难处 / AI 怎么帮 / 上哪个 Agent / 第几批**。第一批选数据现成、风险低、一个月见效的。
- **专用模型**做什么（用他们自己的数据才训得出来的那个），它就是护城河。
- **永远要人确认的红线**（安全、食安、医疗、资金…）。
- **老板最在意的两件事**，以及蓝图 08 写哪个视角（上市 / 扩张 / 合规 / 出海…）。
- **AI 原生组织**：过渡态 8 个部门各配什么 Agent；理想态按哪 4 条价值流组队、6 个职责节点是谁、现场的活怎么按任务派。
- **驾驶舱**：老板每天要看的 6 个数、12+ 个环节状态、4 件要他拍板的事（每件写清派给哪个部门、哪个人、哪个 Agent、哪个职责节点）。

## 3. 写配置

照 `configs/example-tingtao.js` 的结构写 `configs/<公司>.js`。园区先摆建筑（后排生产设施、右侧总部、左侧客户、前排 8 个部门、中心大脑），再写镜头。行业缺造型就去引擎 `KIT` 里加积木（README 有规则）。

文字要求：中文短句、说人话；每步“今天/AI 之后”要具体到这家公司的东西（门店名、产线、系统名、金额量级）；真实数据写出处，其余标“示意”。

## 4. 构建与验收（一项不过就不交）

```bash
node tools/lint.mjs configs/<公司>.js                 # 必须项全过
node tools/build.mjs configs/<公司>.js out
python3 tools/qa.py out/<简称>AI运转全景.html qa        # 后台跑，2–4 分钟
python3 tools/qa_bp.py out/<简称>AI全貌蓝图.html qa
python3 tools/snap.py out/<简称>AI运转全景.html snap    # 24 步逐张截图
```
然后**逐张看截图**（Read 图片），对照第一家的页：
- 每一步镜头对准要讲的那组建筑，没被底部步骤卡挡住；标签不挤成一团。
- 驾驶舱在 1600 / 1180 / 390 三个宽度都不挤、不溢出；图表有数、有动效。
- 蓝图 1440 / 390 两个宽度每个板块都正常，业务地图点得动，运行图能播。
- 页面上没有残留的别家公司名、别的行业词。
不对就改配置（必要时改引擎）重来。

## 5. 发布与交付

1. 3D 页：`publish_files` 发 `index.html`（构建产物），**同时发 `config.js`**（就是这份配置），以后改版从 artifact 里 `read_file` 取回配置，不用重写。
2. 把 3D 页链接填进 `blueprint.cover.link3d`，重新构建，再发布蓝图页（同样带 `config.js`）。
3. `SendUserFile` 发两张离线 HTML（双击就能开，可以发给别人；国内打不开谷歌字体也不影响）。
4. 用 Docs 写两份讲解稿（`NARRATION.md` 的骨架和“操作/说/停下来问/提醒”格式），开头互相链接，链接到对应页面。
5. 回复用户：四个产物各一句；哪些是真实数据（出处），哪些是示意；还缺用户确认的几点。

改版时：取回 `config.js` → 改 → lint/build/QA → 用原 slug 和 `base_version` 重新发布；讲解稿同步改。

## 6. 规矩

- 客户材料（配置、研究笔记、产物、截图）**不进 GitHub**，`tools/publish_github.sh` 会拦。仓库里只有引擎、工具、文档和虚构示例。
- 给客户看的页面和讲解稿里不出现内部讨论（skill、配置、“我们怎么做的”）。
- 引擎改了：更新 `manifest.json` 版本号、`CHANGELOG.md`、本文件标题版本；用示例和至少一份旧配置跑 QA 确认没退化。
- **用户 2026-11-12 定：工具包有任何改动，都自动推送到 GitHub `jesse87wang-bit/TAOSkills` 的 `tao-company-atlas/`（main），不用再问。** 推送：`add_repo`（push）→ 克隆 → `bash tools/publish_github.sh <工具包> <仓库> "<说明>"`；推完在回复里说一句推了哪个版本。工具包里的 SKILL.md 改了，同时发技能更新卡片给用户保存。
- 推送前把所有做过的客户公司名、老板称呼写进 `~/.atlas_denylist`（一行一个；容器每次是新的，每次都要写），`publish_github.sh` 只按白名单拷文件，并用这份名单查一遍，出现客户名就停止。
